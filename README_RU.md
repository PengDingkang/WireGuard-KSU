# WireGuard-KSU

Управление WireGuard VPN на уровне ядра Android через встроенный WebUI KernelSU/APatch.

## Важно при обновлении до v1.2.0: монтирование команд по умолчанию отключено

**При обновлении со старой версии, в которой настройка монтирования не сохранялась, монтирование команд будет отключено по умолчанию. Изменение вступит в силу после перезагрузки.**
Короткие команды `wg` и `wgksu` могут стать недоступны в терминале. Туннели, WebUI, автозапуск и существующие конфигурации это не затрагивает.

| Состояние до установки или обновления | Настройка после установки |
| --- | --- |
| Новая установка | Отключено |
| Старая версия без сохранённой настройки монтирования | Отключено, даже если раньше команды монтировались автоматически |
| Настройка монтирования была сохранена | Прежний выбор включения или отключения сохраняется |

При отключённом монтировании используйте в root-shell полные пути `/data/adb/wireguard/wgksu` и
`/data/adb/wireguard/wg`. Также обновите собственные скрипты, использующие эти команды.
Чтобы вернуть короткие команды, включите **Shell Command Mount** в WebUI и перезагрузите устройство.
В KernelSU требуется доступный метамодуль монтирования. Подробнее: [Дополнительное монтирование команд оболочки](#дополнительное-монтирование-команд-оболочки).

## Основные возможности

- **WireGuard в ядре**: использует встроенный модуль WireGuard в ядрах Linux 5.6+
- **Обработка трафика туннеля ядром**: без пользовательского VPN-демона; фоновые скрипты обслуживают маршруты Endpoint и DNS
- **Несколько интерфейсов**: одновременная работа туннелей wg0, wg1 и других
- **Управление через WebUI**: управление модулем непосредственно в KernelSU/APatch Manager
- **Поддержка трёх root-фреймворков**: Magisk, KernelSU и APatch

## Функции

- Управление через CLI (`start/stop/restart/status/enable/disable/genkey/mount`)
- WebUI KernelSU/APatch:
  - переключение интерфейсов, создание и удаление интерфейсов
  - автоматическая генерация пары ключей при создании интерфейса
  - просмотр IP, порта и публичного ключа интерфейса
  - список Peer: Endpoint, последнее рукопожатие, переданные данные и Allowed IPs
  - редактирование конфигураций с возможностью сохранить и перезапустить
  - генератор пары ключей
  - переключатель автозапуска при загрузке
  - дополнительное монтирование команд оболочки (по умолчанию выключено)
  - журнал запуска, обслуживания маршрутов, предупреждений и ошибок
- При первой установке создаются пара ключей и шаблон конфигурации
- Поддержка распространённых полей стандартного формата конфигурации wg-quick
- Автоматический запуск настроенных интерфейсов при загрузке
- Отображение статуса и IP в списке модулей KernelSU
- Сообщения установщика, описание модуля и статусы `wgksu` учитывают язык системы (английский и русский; для остальных языков используется английский)
- Привязка маршрутов Endpoint к физической сети, чтобы UDP-трафик WireGuard не перехватывался другим VPN/TUN
- Восстановление маршрутов Endpoint после перестроения сети, в том числе при переключении Wi-Fi/мобильной сети
- Дополнительный режим Stay Awake сохраняет доступность WireGuard при выключенном экране, но увеличивает расход батареи

## Требования

Ядро должно поддерживать WireGuard (`CONFIG_WIREGUARD=y`). Установщик проверяет это автоматически.

Большинство ядер KernelSU на базе Linux 5.6 и новее уже включают поддержку WireGuard.

По умолчанию MMRS, meta-overlayfs и другие метамодули монтирования не нужны: WireGuard и WebUI работают без них.
Метамодуль монтирования в KernelSU требуется только для монтирования команд в `/system/bin`.

Для блокировки маршрутов Endpoint необходим `flock` в режиме файлового дескриптора. Модуль сначала использует BusyBox от Magisk/KernelSU/APatch, а также пытается найти совместимую системную реализацию. Если обе недоступны, запуск интерфейса завершится с явной ошибкой вместо работы без закреплённых маршрутов Endpoint.

## Установка

1. Скачайте ZIP из раздела [Releases](../../releases).
2. Установите архив через менеджер Magisk, KernelSU или APatch.
3. При первой установке создаются пара ключей и шаблон `wg0.conf`; публичный ключ отображается в журнале установщика.
4. Заполните данные сервера в `/data/adb/wireguard/wg0.conf` или отредактируйте конфигурацию через WebUI.
5. Перезагрузите устройство для применения установки или обновления. Интерфейсы с включённым автозапуском запустятся автоматически.

Также можно нажать «＋» в WebUI: будет создан интерфейс с новой парой ключей и открыт редактор.

## Управление

Выполняйте команды в root-shell (сначала запустите `su`). Полные пути работают как при включённом, так и при выключенном монтировании команд:

```sh
/data/adb/wireguard/wgksu start              # Запустить все интерфейсы
/data/adb/wireguard/wgksu stop               # Остановить все интерфейсы
/data/adb/wireguard/wgksu restart            # Перезапустить все интерфейсы
/data/adb/wireguard/wgksu start wg0          # Запустить выбранный интерфейс
/data/adb/wireguard/wgksu stop wg0           # Остановить выбранный интерфейс
/data/adb/wireguard/wgksu status             # Показать статусы интерфейсов
/data/adb/wireguard/wgksu enable             # Включить автозапуск
/data/adb/wireguard/wgksu disable            # Отключить автозапуск
/data/adb/wireguard/wgksu stay-awake enable wg0   # Удерживать wakelock и включить Wi-Fi hi-perf при работе wg0
/data/adb/wireguard/wgksu stay-awake disable wg0  # Отключить Stay Awake для wg0
/data/adb/wireguard/wgksu genkey             # Создать новую пару ключей
```

Пользователи KernelSU/APatch могут открыть WebUI модуля в менеджере.

### Дополнительное монтирование команд оболочки

Переключатель **Shell Command Mount** в WebUI определяет, будут ли `wg` и `wgksu` монтироваться в
`/system/bin` для удобного вызова из терминала. По умолчанию он выключен. При отключённом монтировании
туннели, WebUI, автозапуск, восстановление маршрутов, повторное разрешение DNS и Stay Awake продолжают работать.

Для применения изменения настройки монтирования требуется перезагрузка. Настройка действует на весь модуль и сохраняется при обновлении.
Если MMRS отдельно запрещает монтирование этого модуля, разрешите его и в MMRS, чтобы команды стали доступны в системном пути.

В KernelSU монтирование можно включить, только если обнаружен включённый и не помеченный для удаления метамодуль, предоставляющий `metamount.sh`. В противном случае переключатель WebUI будет заблокирован с пояснением, а CLI откажется включать монтирование. Magisk/APatch используют встроенную поддержку монтирования.
Выбор сохраняется в `/data/adb/wireguard/mount_enabled` (`1` — включено, `0` — отключено).
`mount status` показывает сохранённую настройку для следующей загрузки, а не факт уже выполненного монтирования.
`mount supported` сообщает только о наличии поддержки монтирования и не означает, что MMRS разрешил монтировать именно этот модуль.

При отключённом монтировании используйте полные пути:

```sh
/data/adb/wireguard/wgksu start
/data/adb/wireguard/wg show
/data/adb/wireguard/wgksu mount disable  # Сохранить отключённое состояние; применится после перезагрузки
/data/adb/wireguard/wgksu mount enable   # Сохранить включённое состояние; применится после перезагрузки
/data/adb/wireguard/wgksu mount status   # Настройка на следующую загрузку: 1 включено, 0 отключено
/data/adb/wireguard/wgksu mount supported # Поддержка монтирования: 1 есть, 0 нет
```

Модуль всегда вызывает собственные инструменты из `/data/adb/wireguard/` и не зависит от системного пути команд.

### Журналы

**Runtime Log** в WebUI показывает общий для всех интерфейсов журнал запуска при загрузке, обслуживания маршрутов, предупреждений и ошибок. `wg0 up` означает успешный запуск интерфейса, а не ошибку. Если записей нет, отображается **No log entries**.
В интерфейсе показываются последние 50 строк. Очистка удаляет журнал работы всех интерфейсов.

Для сохранения существующих записей и совместимости с работающими скриптами путь остаётся прежним: `/data/adb/wireguard/error.log`.
При запуске во время загрузки stdout и stderr команд дописываются в этот файл. При ручном запуске вывод остаётся в терминале или WebUI; в журнал попадают только сообщения, явно записанные модулем.

Изменения DNS-адресов Endpoint записываются отдельно в `/data/adb/wireguard/reresolve.log`.
Их можно посмотреть в **DNS Re-resolve → Re-resolve Log**. Сопутствующее обслуживание маршрутов и ошибки по-прежнему записываются в журнал работы.

## Конфигурация

Файлы конфигурации хранятся в `/data/adb/wireguard/` и используют стандартный формат WireGuard:

```ini
[Interface]
PrivateKey = YOUR_PRIVATE_KEY
Address = 10.0.0.2/24
DNS = 1.1.1.1
MTU = 1420

[Peer]
PublicKey = SERVER_PUBLIC_KEY
Endpoint = server.example.com:51820
AllowedIPs = 10.0.0.0/24
PersistentKeepalive = 25
```

Поддерживаются несколько файлов (`wg0.conf`, `wg1.conf` и т. д.); каждый файл соответствует отдельному интерфейсу.

Поддерживаются `Address`, `DNS`, `MTU` и распространённые поля WireGuard, используемые `wg setconf`.
Хуки wg-quick `PreUp`, `PostUp`, `PreDown`, `PostDown` не выполняются; параметры `Table` и `SaveConfig` не реализованы. Не полагайтесь на них для дополнительной настройки сети.

### Закрепление маршрутов Endpoint

При запуске интерфейса модуль ожидает появления физической сети и DNS, затем добавляет более специфичный host route для каждого Peer `Endpoint`. Это направляет внешний UDP-трафик WireGuard через физическую сеть (приоритет: `wlan`, затем `eth`, затем мобильная сеть) и не позволяет другому Android VPN/TUN перехватить трафик Endpoint.

Если Android перестраивает сеть после выключения экрана, переключения Wi-Fi или смены мобильной сети, модуль периодически проверяет нижележащий маршрут для Endpoint работающих Peer и закрепляет его повторно, если маршрут исчез или указывает на неверное устройство. По умолчанию эта лёгкая проверка выполняется примерно раз в 30 секунд и не запускает DNS-запросы.

Для Endpoint, заданных доменами, изменения DNS обрабатываются циклом повторного разрешения. Интервал по умолчанию — 120 секунд; его можно уменьшить в настройках DNS re-resolve WebUI. Более короткий интервал увеличивает число пробуждений устройства и DNS-запросов при выключенном экране.

### Доступность при выключенном экране

WireGuard в ядре не использует Android foreground service `VpnService`. На некоторых устройствах после выключения экрана Wi-Fi/CPU переходят в энергосберегающий режим, из-за чего входящие подключения к адресу туннеля могут перестать работать даже при настроенном `PersistentKeepalive`.

Чтобы сохранить доступность извне при выключенном экране, включите Stay Awake для интерфейса:

```sh
/data/adb/wireguard/wgksu stay-awake enable wg0
```

Если интерфейс уже работает, настройка применяется сразу; иначе она вступит в силу при следующем запуске интерфейса. Модуль записывает имя в `/sys/power/wake_lock` и запускает `cmd wifi force-hi-perf-mode enabled`. При остановке интерфейса или отключении Stay Awake wakelock снимается, а включённый модулем Wi-Fi hi-perf выключается.

Для `cmd wifi force-hi-perf-mode` требуется Android 10 или новее. На Android 9 команда может отсутствовать: ошибка попадёт в журнал, но модуль всё равно попробует установить wakelock.

Этот режим мешает устройству нормально переходить в глубокий сон и может значительно увеличить расход батареи. Включайте его только для разработки, удалённого обслуживания или устройств с постоянным питанием.

### Создание пары ключей

Выполните команду в root-shell телефона:

```sh
/data/adb/wireguard/wgksu genkey
```

На любом устройстве с инструментом `wg`:

```bash
wg genkey | tee privatekey | wg pubkey > publickey
```
